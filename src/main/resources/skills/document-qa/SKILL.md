## 适用场景
用户的问题需要以上传文档内容为事实依据时使用本技能。不适用于纯闲聊、纯公共网络信息或纯计算类问题。

## 工作流
1. **定位文档**：如果不确定用户指的是哪个文档（如"第一个文档""那个报告"），先调用 `document_list` 获取文档清单（id、标题、状态），再结合上下文确定 documentId。文档状态不是 COMPLETED 的，直接告知用户该文档尚未处理完成，不要检索。
2. **检索证据**：调用 `rag_search`。单文档问题必须带 `documentId`；跨文档问题可不带。查询词使用改写后的完整问题，不要只用代词。
3. **评估证据是否充分**：
   - 命中的 chunk 与问题相关 → 进入作答。
   - 命中为空或明显不相关 → 换一种表述再检索一次（同义词、关键名词展开）。
   - 两次检索仍不充分 → 直接 finish，如实说明文档中未找到相关内容，禁止编造。
4. **作答**：只依据检索到的证据回答，区分"文档明确说的"与"由文档内容推断的"。

## 铁律
- 每一个具体事实必须能对应到某条检索证据；没有证据支撑的断言一律不写。
- 保留证据中的引用标号（[S1]、[S2]…），在正文中标注在对应句子末尾。
- 不要把多个文档的内容混为一谈；跨文档对比时明确标出各自来源。
- 如果 rag_search 返回了置信度信息，在答案中简要说明证据强弱。

## 输出模板
```
（正文回答，句末带 [S1] 式引用标号）

**引用来源**
- [S1] 《文档标题》(id=..., chunk #...)：一句话说明该证据内容
- [S2] ...

（证据不足时）**说明**：文档中未找到与"..."直接相关的内容，以上部分基于...推断。
```
